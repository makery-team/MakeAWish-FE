# 🚀 MakeAWish 프로젝트 업데이트 및 테스트 가이드 (2026.07.20)

본 문서는 최근 발생했던 프론트엔드 및 백엔드 연동 이슈들을 해결한 내역을 설명하고, 개발 환경에서 이를 테스트하는 방법을 안내합니다.

---

## 1. 🛠️ 무엇을 개발/수정했나요?

최근 발생했던 "1시간 후 토큰 만료 시 앱 먹통(500 에러) 현상"을 해결하기 위해 백엔드와 프론트엔드 양쪽에서 대대적인 보수 공사를 진행했습니다.

### 🛡️ 백엔드 (MakeAWish-BE)
- **보안 구멍 수리 (`SecurityConfig.java`)**
  - 기존에는 `/api/ai-agent/**` (AI 채팅 및 인페인팅) 경로가 `permitAll()`로 설정되어 있어, 토큰이 만료된 유저도 통과시켜 주었습니다. 
  - 이로 인해 인증 정보(`User`)가 없는 상태로 DB에 접근하다가 서버가 터지는(500 에러) 문제가 있었습니다.
  - 이를 **`authenticated()`**로 꽉 잠가서, 만료된 토큰을 가져오면 정상적으로 **401(권한 없음) 에러**를 뱉어내도록 수정했습니다.
- **안전장치 추가 (`AiInpaintedDesignService.java`)**
  - 원본 포트폴리오를 찾지 못했을 때 서버가 에러를 던지며 죽어버리는 대신, `null`로 부드럽게 처리하도록 수정했습니다.
- **이미지 URL 강제 절삭 버그 해결 (`AiInpaintedDesignService.java`)**
  - 기존에는 백엔드가 프론트엔드로부터 받은 AWS S3 이미지 주소에서 `?` 뒤의 서명(Signature) 토큰을 무작정 잘라내어 AI 서버가 이미지를 다운로드하지 못하는 치명적인 버그가 있었습니다.
  - 이 `split("\\?")[0]` 코드를 삭제하여 원본 주소를 있는 그대로 안전하게 넘겨주도록 수정했습니다.

### 🌐 프론트엔드 (MakeAWish-FE)
- **통신 자동 갱신 장착 (`ai.ts`)**
  - 백엔드가 이제 정상적으로 401 에러를 뱉기 시작했으므로, 프론트엔드도 이에 대응해야 합니다.
  - 옛날 방식의 `fetch`를 버리고, 401 에러를 감지하면 몰래 '토큰 갱신 API'를 찔러 새 토큰을 받아온 뒤 알아서 재요청하는 똑똑한 **`fetchWithAuth`** 래퍼(Wrapper)로 전면 교체했습니다.
  - 이제 1시간이 지나도 앱이 먹통되지 않고 자연스럽게 서비스가 이어집니다!
- **임시 방편(Base64) 제거 및 통신 정상화 (`editor-view.tsx`)**
  - 백엔드의 URL 절삭 버그를 피하기 위해 임시로 추가했던 프론트엔드의 Base64 이미지 변환 코드를 깨끗하게 지우고, 서버 메모리와 용량을 절약하는 원래의 가벼운 'URL 직접 전송' 방식으로 되돌렸습니다.

## 2. 🧪 백엔드 배포 없이 로컬에서 테스트하는 방법

유저님의 질문: *"백엔드 배포 없이 로컬에서 테스트해도 괜찮나요?"*
**답변:** 네! 하지만 프론트엔드가 AWS 클라우드(예전 버전 백엔드)를 바라보게 두면 에러가 똑같이 발생합니다. 따라서 **내 컴퓨터(로컬)에서 백엔드를 직접 켜고 연결해서 테스트해야 합니다.**

### [Step 1] 로컬 백엔드 서버 켜기
1. IntelliJ 등에서 `MakeAWish-BE` 프로젝트를 엽니다.
2. `MakeAWishBeApplication`을 실행하여 로컬 서버(보통 `http://localhost:8080`)를 켭니다.

### [Step 2] 로컬 AI 서버 켜기
1. `MakeAWish-AI` 폴더에서 파이썬 가상환경을 켜고 `uvicorn main:app --reload`로 AI 서버(`http://localhost:8000`)를 켭니다.

### [Step 3] 프론트엔드 방향 틀기 (Localhost 연결)
1. `MakeAWish-FE` 폴더 최상단에 있는 `.env` 파일(없으면 만드세요!)을 엽니다.
2. 아래와 같이 AWS 주소 대신 내 컴퓨터 주소를 바라보게 설정합니다.
   ```env
   EXPO_PUBLIC_API_URL=http://localhost:8080
   ```
   *(안드로이드 에뮬레이터를 쓰신다면 `http://10.0.2.2:8080` 일 수 있습니다.)*
3. 프론트엔드 서버를 껐다가 `npm start`로 다시 켭니다.

### [Step 4] 진짜 테스트해보기!
- 앱에 접속해서 아무렇게나 로그인을 합니다.
- **일부러 토큰 만료시키기 (꿀팁):** 로컬 백엔드 DB(H2 등)를 조작할 필요 없이, 앱을 켜두고 밥을 먹고 오거나(1시간 경과), 혹은 `Application` 탭(AsyncStorage)에서 `auth_token` 값을 살짝 이상한 글자로 바꿔치기해 봅니다.
- 그 상태에서 AI 채팅창에 말을 걸거나 케이크 인페인팅을 시도합니다.
- **성공 확인:** 에러 없이 정상적으로 결과가 돌아온다면, 프론트엔드의 `fetchWithAuth`가 만료된 토큰을 버리고 새로 발급받아 재요청하는 마법이 성공적으로 작동한 것입니다! 🎉
