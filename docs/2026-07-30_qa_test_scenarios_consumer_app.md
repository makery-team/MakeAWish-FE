# [MakeAWish-FE] 소비자용 앱 마일스톤 1~4 통합 QA 테스트 검증 시나리오

- **작성일:** 2026-07-30
- **대상 브랜치:** `test/consumer-release-qa` (마일스톤 1~4 통합 검증 브랜치)
- **테스트 환경:** Windows / React Native Expo Simulator 및 실제 단말기

---

## [Milestone 1] 주문 파이프라인 및 상태 동기화 (`feat/consumer-order-pipeline`)

### 시나리오 1-1. 내 주문 목록 실시간 조회 및 4단계 진행 상태 검증
- **전제 조건:** 유효한 사용자 계정 로그인 (`/(auth)/login`)
- **테스트 단계:**
  1. 앱 하단 네비게이션 또는 마이페이지에서 **"주문 내역(`/orders`)"** 화면으로 이동합니다.
  2. 각 주문 카드 내 **4단계 진행 상태(견적 대기 -> 입금 대기 -> 제작 중 -> 픽업 완료)**가 실제 백엔드 상태(`PENDING_QUOTE`, `APPROVED`, `IN_PROGRESS`, `COMPLETED`, `CANCELED`)에 맞게 하이라이트되는지 확인합니다.
     - **견적 대기(`PENDING_QUOTE`)**: `✨ 매장에서 견적을 확인 중이에요`
     - **입금 대기(`APPROVED`)**: `💳 주문 수락 완료! 입금을 진행해주세요`
     - **제작 중(`IN_PROGRESS`)**: `👩‍🍳 케이크를 열심히 제작 중이에요`
     - **픽업 완료(`COMPLETED`)**: `🎉 픽업이 완료되었습니다`
     - **주문 취소(`CANCELED`)**: `❌ 주문이 취소되었습니다`
  3. 목록을 아래로 스와이프(Pull-to-Refresh)하여 새로고침 스피너가 작동하고 백엔드(`/api/orders/my`)에서 최신 주문 내역을 동기화하는지 확인합니다.
- **예상 결과:** Mock 데이터가 아닌 실제 백엔드의 주문 목록이 표시되어야 하며, 각 주문 카드의 4단계 상태 아이콘 및 안내 메시지가 정확히 일치해야 합니다.

### 시나리오 1-2. 주문 완료(`COMPLETED`) 시 리뷰 작성 CTA 조건 검증
- **테스트 단계:**
  1. 주문 내역 목록에서 주문 카드를 확인합니다.
  2. 주문 상태가 **`COMPLETED` (픽업 완료)**인 주문 카드의 경우, 하단에 **"⭐ 리뷰 작성하기"** CTA 버튼이 정상 표시되는지 확인합니다.
  3. 주문 상태가 **`PENDING_QUOTE` (견적 대기), `APPROVED` (입금 대기), `IN_PROGRESS` (제작 중)** 등 픽업 완료 전 상태인 주문 카드의 경우, 리뷰 작성 버튼이 표시되지 않는지 확인합니다.
- **예상 결과:** 오직 **픽업 완료(`COMPLETED`)** 상태인 주문 카드에 한해서만 리뷰를 작성할 수 있어야 합니다.

## [Milestone 2] AI 에디터 -> 1:1 상담 -> 주문서 파이프라인 (`feat/consumer-ai-editor-pipeline`)

### 시나리오 2-1. AI 인페인팅 도안 생성 및 채팅 상담 연계 검증
- **테스트 단계:**
  1. 하단 **"AI 에디터(`/editor`)"** 탭 진입 후 케이크 이미지를 선택하고 프롬프트를 입력하여 커스텀 도안 생성(Inpainting) 기능을 사용합니다.
  2. 완성된 커스텀 이미지 하단의 **"상담하기"** 버튼을 누르거나 매장 상세 화면에서 "이 도안으로 상담하기"를 선택합니다.
  3. 매장 선택 후 1:1 채팅 화면(`/chat/[id]`)으로 자동 진입할 때, 상담 Context(`inquiryContext`)에 생성된 커스텀 이미지(`customImage`) 및 요구사항 메타데이터가 정상 전달되어 첨부되는지 확인합니다.
- **예상 결과:** AI 에디터에서 만든 이미지와 메타 정보가 유실 없이 채팅 상담창으로 이어져야 합니다.

### 시나리오 2-2. 채팅 상담 중 '주문서 작성하기' CTA 및 Pre-fill 검증
- **테스트 단계:**
  1. 1:1 채팅 화면 상단/하단에 위치한 **"주문서 작성하기"** CTA 버튼을 클릭합니다.
  2. 주문서 작성 화면(`/order-sheet`) 진입 시, 상담 중이던 **매장명(`shopName`), 커스텀 케이크 이미지(`cakeImage`), 희망 픽업일** 등이 자동으로 채워져(Pre-fill) 있는지 확인합니다.
  3. 레터링 문구와 세부 요청사항을 입력한 후 "주문 신청"을 완료합니다.
- **예상 결과:** 입력한 정보 그대로 주문이 접수되며, 주문 목록(`/orders`) 상단에 실시간으로 반영되어야 합니다.

## [Milestone 3] 지도/탐색 실서버 API 100% 연동 (`feat/consumer-map-real-data`)

### 시나리오 3-1. 탐색(`/explore`) 화면 실서버 피드 로딩 및 Fallback 제거 검증
- **테스트 단계:**
  1. 앱 메인 화면인 **탐색(`/explore`)** 탭으로 진입합니다.
  2. 화면 로딩 시 백엔드(`/api/portfolios/search`, `/api/stores/nearby`)와 통신하여 실제 등록된 케이크 포트폴리오 및 매장 목록이 렌더링되는지 확인합니다.
  3. 네트워크 오류 또는 없는 데이터 조회 시 기존의 하드코딩된 Mock Fallback 데이터가 렌더링되지 않고, 안전한 빈 상태 안내 또는 에러 배너가 출력되는지 확인합니다.
- **예상 결과:** Mock 데이터 없이 100% 실서버 데이터만 표시되며, 오류 상황에서도 Fallback 하드코딩이 출력되지 않아야 합니다.

### 시나리오 3-2. 주변 매장 지도 마커 및 샵 상세 연동 검증
- **테스트 단계:**
  1. 탐색 화면 상단의 지도 뷰 토글 버튼을 눌러 지도 모드로 전환합니다.
  2. 지도 상의 마커들이 실제 매장의 위치 좌표(위경도)에 표시되는지 확인합니다.
  3. 마커를 클릭하여 하단 시트에 매장명, 주소, 전화번호(`phone`)가 정상 노출되는지 확인하고, "매장 보기" 누를 시 해당 샵 상세(`/shop/[id]`) 화면으로 이동하는지 확인합니다.
- **예상 결과:** 지도 좌표 마커와 샵 상세 페이지 이동이 실제 데이터 기반으로 일치해야 합니다.

## [Milestone 4] 찜하기 실시간 연동 및 마이페이지 동기화 (`feat/consumer-favorites-sync`)

### 시나리오 4-1. 찜하기(좋아요) 토글 및 찜 목록 실시간 동기화
- **테스트 단계:**
  1. 탐색 화면 또는 케이크 슬라이더에서 하트(찜하기) 아이콘을 클릭합니다.
  2. 마이페이지(`/mypage`)로 이동하여 상단 프로필 카드의 **"찜한 가게"** 카운트 숫자가 즉시 1 증가했는지 확인합니다.
  3. **"찜한 가게"** 숫자 카드를 클릭하여 찜 목록(`/favorites`) 화면으로 이동한 뒤, 방금 찜한 케이크/가게 목록이 정상 출력되는지 확인합니다.
  4. 찜 목록에서 하트 버튼을 눌러 찜을 해제한 뒤, 마이페이지로 돌아왔을 때 카운트가 즉시 1 감소하는지 확인합니다.
- **예상 결과:** 좋아요 등록/해제가 백엔드 및 로컬 상태에 즉시 동기화되고 숫자 카운트와 목록이 일치해야 합니다.

### 시나리오 4-2. 마이페이지 3대 통계 실시간 동기화 및 Pull-to-Refresh 검증
- **테스트 단계:**
  1. 마이페이지(`/mypage`) 진입 시 상단의 **"주문 내역", "찜한 가게", "작성 리뷰"** 수치가 0 하드코딩이 아닌, 실제 내 계정의 활동 수치로 바인딩되는지 확인합니다.
  2. 화면을 아래로 당겨 스와이프 새로고침(Pull-to-Refresh) 시 로딩 스피너가 돌며 3대 수치를 백엔드에서 재조회하는지 확인합니다.
  3. **"작성 리뷰"** 숫자 카드를 클릭하여 내 리뷰 목록(`/reviews`) 화면으로 이동하고 수치와 목록이 일치하는지 확인합니다.
- **예상 결과:** 탭 전환이나 화면 포커스(`useFocusEffect`) 시마다 항상 실시간 통계가 반영되어야 합니다.
