# [Architecture Decision] 매장 요일별 운영시간 명세 및 리뷰 데이터 무결성 아키텍처 (Option A)

- **작성일:** 2026-07-27
- **관련 컴포넌트:** `MakeAWish-BE (Store / data.sql)`, `MakeAWish-FE (ShopDetail / renderOperatingHours)`, `Seller Web App`
- **의사결정자:** 개발팀 / 아키텍처 리뷰

---

## 1. 문서 목적
본 문서는 매장 프로필 조회 및 수정 API(`/api/stores/profile`)의 `hours` 필드(`String` 타입)를 기반으로 **[사장님 웹앱(Seller Web App) ↔ 백엔드(Backend) ↔ 사용자 앱(User App FE)]** 3자 간 요일별 운영 시간 및 휴무일 데이터를 일관되게 동기화하기 위한 **공식 규격(Convention)**을 정의합니다.

또한 숫자 하드코딩 지양 원칙에 따른 **매장 리뷰 개수(`reviewCount`) 및 평점(`rating`) 무결성 보장 방식**을 명확히 기록합니다.

---

## 2. 요일별 운영시간 규격 의사결정 배경

### 가. 문제 상황
- **사장님 웹앱 UI**: 요일별(`월~일`) 영업 시작~종료 시간 및 `휴무` 체크박스를 입력하는 정밀 폼(Form) 구조를 가짐.
- **백엔드 API 명세서 & DB 스키마**: `hours` 컬럼이 단순 문자열(`VARCHAR`) 타입의 단일 필드로 정의되어 있음.

### 나. 아키텍처 비교 및 최종 선택: Option A (JSON String Convention)
- **Option A (채택)**: 백엔드 API 명세 및 DB 스키마 변경(`hours: String` 유지) 없이, 문자열 내부에 **JSON 형식의 요일별 운영시간 객체 문자열**을 약속하여 전송/조회하는 규격화 방식.
  - **장점**: 
    1. 백엔드 스키마 변경 및 DB 마이그레이션 불필요 (API 명세서 충돌 ZERO).
    2. 프론트엔드 파서를 통해 원하는 스타일(요일별 테이블 카드)로 100% 동적 렌더링 가능.
    3. 일반 텍스트(`"10:00 - 20:00"`)가 입력될 경우에도 자연스러운 텍스트 출력이 보장되는 **하위 호환성 100%**.
- **Option B (기각)**: 백엔드 DTO 및 DB 컬럼을 JSON 컬럼이나 별도의 운영시간 테이블로 분리하는 방식 (공사 규모가 크고 기존 통신 명세와 충돌 가능성 존재).

## 3. 요일별 운영시간 공식 페이로드 규격 (Data Spec)

### 가. 사장님 웹앱 → 백엔드 전송 규격 (`PATCH /api/stores/profile`)
사장님 웹앱에서 "저장하기"를 수행할 때, 7개 요일의 운영 시간 상태를 아래의 JSON String 형식으로 묶어 `hours` 필드에 담아 전송합니다.

```json
{
  "name": "어드민 베이커리",
  "hours": "{\"mon\":\"09:00 - 20:00\",\"tue\":\"09:00 - 20:00\",\"wed\":\"09:00 - 20:00\",\"thu\":\"09:00 - 20:00\",\"fri\":\"09:00 - 20:00\",\"sat\":\"10:00 - 18:00\",\"sun\":\"휴무\"}"
}
```

- **지원 키(Key)**: 
  - 영문 키: `"mon"`, `"tue"`, `"wed"`, `"thu"`, `"fri"`, `"sat"`, `"sun"`
  - 한글 키(호환): `"월"`, `"화"`, `"수"`, `"목"`, `"금"`, `"토"`, `"일"`
- **휴무일 표기 규격**: `"휴무"` 또는 `"Closed"` (프론트엔드 파서에서 붉은색 텍스트 강조 처리됨).

## 4. 컴포넌트별 구현 세부사항

### 1) MakeAWish-BE (백엔드)
- `Store.java`의 `hours` 필드는 `String` 타입으로 원문 그대로 DB `stores` 테이블에 보존됩니다.
- 초기 개발 시드 데이터(`src/main/resources/data.sql`)의 1번 매장(`어드민 베이커리`)에 공식 Option A 규격을 반영하여 전체 시스템 검증의 기준 데이터로 활용합니다.
  ```sql
  -- Store 1 hours column
  '{"mon":"09:00 - 20:00", "tue":"09:00 - 20:00", "wed":"09:00 - 20:00", "thu":"09:00 - 20:00", "fri":"09:00 - 20:00", "sat":"10:00 - 18:00", "sun":"휴무"}'
  ```

### 2) MakeAWish-FE (사용자 앱 프론트엔드)
- `components/shop-detail.tsx` 내에 **스마트 파서(`renderOperatingHours`)**를 탑재했습니다.
- 동작 로직:
  1. **JSON 문자열 파싱**: `hours` 필드가 `{...}` JSON 형식인 경우, 자동으로 `월~일` 7줄의 핑크빛 테이블 카드로 렌더링하며 휴무일은 붉은색(`color: #FF4D4F`) 볼드 폰트로 강조합니다.
  2. **줄바꿈 문자열 파싱**: 개행 문자(`\n`)가 포함된 문자열은 각 줄을 개별 텍스트 줄로 출력합니다.
  3. **일반 한 줄 문자열 (하위 호환)**: 기존 텍스트(`"11:00 - 21:00"`)도 예외 없이 정상 출력됩니다.

---

## 5. 리뷰 데이터 및 평점 통계 무결성 (No Hardcoding Principle)

### 가. 프론트엔드 하드코딩 완전 제거
- 사용자 앱(`MakeAWish-FE`)의 모든 매장 상세 및 카드 컴포넌트에는 숫자 하드코딩(`150`, `2`, `1` 등)이 **단 1도 존재하지 않습니다**.
- 100% 백엔드 API 응답 객체의 `storeData.reviewCount` 및 `storeData.rating` 속성을 받아서 동적 렌더링합니다.

### 나. 백엔드 시드 데이터 무결성 100% 검증
- 초기 시드(`data.sql`)의 `stores` 테이블에 기록된 `review_count` 및 `rating` 기본값을 실제 `reviews` 테이블에 인서트된 레코드 개수 및 평점과 100% 일치시켰습니다.
  - `1번 어드민 베이커리`: `⭐ 5.0 (2)` (리뷰 2개)
  - `2번 달콤달콤 케이크`: `⭐ 5.0 (1)` (리뷰 1개)
  - `3번 위시 케이크`: `⭐ 4.5 (2)` (리뷰 2개)
  - `4번 해피 베이킹`: `⭐ 5.0 (1)` (리뷰 1개)
  - `5번 러블리 디저트`: `⭐ 5.0 (1)` (리뷰 1개)
- 실제 프로덕션 단계에서는 리뷰 생성/삭제 및 관리 서비스(`ReviewService.java`)를 통해 SQL 쿼리로 실시간 집계되어 동적으로 갱신됩니다.
