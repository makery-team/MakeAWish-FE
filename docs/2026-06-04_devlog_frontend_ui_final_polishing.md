# 🛠️ 프론트엔드 UI/UX 폴리싱 및 비동기 트러블슈팅 아카이브

MakeAWish 프론트엔드 프로젝트의 최종 UI/UX 완성도 개선 및 백엔드 API 연동 과정에서 해결된 주요 트러블슈팅 사례와 해결 로직 기록입니다.

---

## 1. 전역 세션(Auth) 및 토큰 만료(401) 자동 처리

### 현상
- 유효기간이 지난 `accessToken`으로 API 요청 시 `401 Unauthorized` 에러가 반환되며, 로컬 스토리지에 `refreshToken`이 없거나 갱신 실패 시 무한 로딩 및 에러 화면에 갇히는 현상 발생.

### 해결 로직
- **API 인터셉터 방어 (`utils/api.ts`):** `fetchWithAuth` 내부에 토큰 재발급 실패(`refreshAccessToken() === null`) 시 기기 내 모든 토큰을 즉시 제거하도록 처리했습니다.
- **전역 이벤트 브로드캐스팅 (`DeviceEventEmitter`):** 훅(Hook)을 사용할 수 없는 서비스/유틸리티 레이어에서 UI 컨트롤러에게 이벤트를 알리기 위해 `DeviceEventEmitter.emit('EXPIRED_SESSION')` 패턴을 채택했습니다.
- **세션 초기화 리스너 (`context/AuthContext.tsx`):** 앱 최상위 컨텍스트의 `useEffect`에서 해당 이벤트를 수신하고, 세션 초기화(`signOut()`) 및 알림 표시와 동시에 안전하게 로그인 화면으로 라우팅되도록 설계했습니다.

---

## 2. 네비게이션 스택 제어 및 UX 흐름

### 현상
- 매장 상세 페이지 또는 AI 커스텀 캔버스 에디터에서 "이 시안으로 상담하기" 액션 수행 시, 사용자의 기대(홈/채팅 탭 이동)와 달리 직전 상세 페이지로 돌아가는 스택 꼬임 현상.

### 원인 및 해결 로직
- Expo Router의 `router.back()`은 히스토리 스택의 직전 경로로만 이동하므로 `상세페이지 -> 에디터` 진입 후 퇴장 시 흐름이 깨지는 원인이었습니다.
- 이를 해결하기 위해 `app/editor/[id].tsx` 및 `app/shop/[id].tsx`의 라우팅 콜백에서 스택을 새로 초기화하며 최상단 메인 탭으로 이동하는 **`router.replace('/(tabs)')`** 메서드를 적용하여 일관된 유저 여정을 보장했습니다.

## 3. 비동기 데이터 렌더링 시 UI 깜빡임 방어

### 현상
- 지도에서 특정 매장을 클릭하고 상세 페이지 진입 시, 짧은 순간 "매장 정보를 찾을 수 없습니다"라는 빈 화면 에러가 표출된 후 정상 화면이 렌더링되는 문제.

### 원인 및 해결 로직
- 비동기 API 통신 시작 직후의 `storeData` 상태가 `null`이므로, 데이터 페칭 여부(`isLoadingDetail`)를 구분하지 않은 조건부 렌더링이 즉시 예외 뷰를 렌더링하고 있었습니다.
- 로딩 상태 변수의 조건 검사를 1순위로 승격시켜 데이터 로딩 중에는 `ActivityIndicator`가 표출되고 완결 후 상세 데이터가 바인딩되도록 `components/shop-detail.tsx`를 교정했습니다.

## 4. 점진적 릴리즈를 위한 기능 토글 방어 로직

### 현상
- 매장 상세의 "1:1 채팅하기" 버튼 클릭 시 웹소켓 1006 에러로 연결이 실패하는 현상.
- 채팅방 생성 API(`makeRoom`)에는 상대방 판매자 ID(`sellerId`)가 필요하나 현재 버전의 `StoreResponse` DTO에는 해당 매핑 필드가 준비되지 않은 상태였습니다.

### 해결 로직
- API 명세서 확장 및 백엔드 반영 대기 전까지 앱의 안정성을 확보하기 위해 해당 이벤트 핸들러에 Graceful Degradation(우아한 기능 저하) 방어 로직을 삽입했습니다.
- 에러를 유발하는 라우팅 코드를 차단하고 `Alert.alert('안내', '현재 점검 중입니다.')`를 렌더링하여 안정적인 앱 시연 환경을 유지합니다.
